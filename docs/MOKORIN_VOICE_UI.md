## 4. 会話の流れ

```
もこりん：こんにちは。今、緊張してる？            ［少し緊張してる］［かなり緊張してる］［今は落ち着いてる］
あなた　：かなり緊張してる
もこりん：そっか。何か予定があるの？             ［面接・発表］［試合・大会］［大切な予定］［作業・集中］［特に予定はない］［その他］
あなた　：これから就活の面接なんだ
もこりん：面接前なんだね。今は落ち着いて座ってる？それとも移動してきたところ？
                                              ［座って落ち着いてる］［階段・移動してきた］［走ってきた］…（複数可→［これで決定］）
あなた　：さっき階段を上ってきた
もこりん：教えてくれてありがとう。面接前で、階段を上った直後なんだね。この状況で測定してみようか？
［この状況で測定する］→ 既存の applyAndProceed() → MeasurementContext(scene: interview, conditions: [stairs])
```

（端末内の定型文での実際の文言。テストで完全一致を確認）

- 回答は 音声・文字・選択肢 のどれでもよい。1つの発言に複数の情報があればまとめて進み、答えた内容は聞き直さない
- 曖昧な答えには追加で質問する。緊張の質問は2回はっきりしなければ先へ進む（測定できなくならないように）
- 「今は落ち着いてる」「特に予定はない」「座って落ち着いてる」でも測定まで進める
- **主観的な緊張（少し／かなり／落ち着いてる）は会話と表情だけに使い、MeasurementContext・StressScoreCalculator・保存データには入れない**

## 5. 音声対話（1ターンずつ）

| 段階 | 実装 |
|---|---|
| 開始 | マイクボタンを押したときだけ。初回は OS の許可（音声認識・マイク）を求める |
| 認識 | `SFSpeechRecognizer`（日本語）＋ `AVAudioEngine`。端末内で認識できる場合は `requiresOnDeviceRecognition`。途中の文字を画面に表示 |
| 終了・送信 | 約1.5秒の無音、もう一度マイクを押す、または最長30秒で終了し、確定した文字を会話へ送る |
| 返答 | 外部AI（同意＋サーバー設定時）または端末内の判定。表情・動作を変える |
| 読み上げ | `AVSpeechSynthesizer`（日本語）。初めてマイクを使うと ON、ボタンで切り替え。読み上げ中はもこりんの口が動く |
| 次のターン | **利用者がもう一度マイクを押したときだけ**（自動で録音しない） |

- 読み上げ中は録音しない。読み上げ中にマイクを押すと読み上げを止めてから録音する（もこりん自身の声を認識しない）。二重再生しない
- 録音中・処理中・読み上げ中を画面に表示。画面を閉じる・アプリが背面に回ると録音と読み上げを止める
- 権限がない・使えない・聞き取れないときは理由を表示し、文字入力・選択肢で続けられる
- 音声データ・認識結果はログに出さない（状態と文字数のみ）
- 権限の説明文（Info.plist）: `NSMicrophoneUsageDescription`「もこりんと声で話すときに、マイクボタンを押してから話し終えるまでの間だけ音声を聞き取るために使用します。」／`NSSpeechRecognitionUsageDescription`「もこりんに話しかけた声を文字に変換するために使用します。変換した文字は会話にのみ使います。」（`project.pbxproj` の iOS アプリの Debug/Release に追加。これ以外の設定は変更なし）

## 7. 実機の通信経路（調査結果）

- 接続先は DEBUG の環境変数 `MW_INSIGHT_BASE_URL`（または UserDefaults）。http はループバック（localhost / 127.0.0.1）だけ許可している
- **127.0.0.1 は「その端末自身」を指す。** シミュレーターでは Mac 自身なのでローカルサーバーに届くが、実機の iPhone では iPhone 自身を指すため届かない
- 対応: 実機でループバックを指定している場合は送信せず、「実機では 127.0.0.1 は iPhone 自身を指すため、Mac のサーバーに接続できません」と表示する（AI の応答として扱わない。`ServerConnectionDiagnostics`）
- セキュリティ設定（ATS・http の許可範囲・サーバーの待ち受けアドレス）は変更していない。実機で試す方法の候補（どれも統合責任者の判断が必要）:
  1. シミュレーターで試す（現状のまま動く）
  2. サーバーを Cloudflare にデプロイして https で接続する（承認・認証の整備が必要）
  3. 開発用に Mac の LAN アドレスで待ち受け、DEBUG ビルドだけローカルネットワークの http を許可する（ATS の例外追加・待ち受け範囲の拡大を伴うため、今回は実施していない）

## 9. 不具合: マイクを押した直後に「うまく聞き取れなかった」（2026-11-05 修正）

### 症状（実機で観察）
マイクボタンを押すと、話す前にほぼすぐ録音が終わり「うまく聞き取れなかったよ。もう一度マイクを押すか、文字で教えてね。」が表示された（吹き出しは最初の定型文のまま）。

### この文言に到達した経路（修正前の `MokorinVoice.swift`）
1. 認識タスクのエラーが、まだ文字を聞き取っていない時点で届いた（エラーの種類は問わず同じ文言）
2. 録音を終えたときの文字が空だった（無音タイマー・最長タイマー・ボタンでの終了のどれでも）

### コードで確認できた原因
| # | 原因 | 影響 |
|---|---|---|
| 1 | **前の録音の遅れたコールバックを捨てていなかった**。`start()` の最初で前の認識タスクを取り消すと、そのタスクの取り消しエラーが後から届く。新しい録音では `finished=false`・文字が空のため、それを今の失敗として扱い、新しい録音を片付けて文言を表示していた | 2 回目以降のマイクで直後に失敗しうる |
| 2 | **空の途中結果でも「話し始めた」とみなしていた**。結果が届くたびに無発話の 8 秒タイマーを 1.8 秒の無音タイマーに置き換えていたため、空の結果が 1 回届くだけで約 1.8 秒後に空の文字で終了し、文言を表示していた | 押して約 2 秒で失敗しうる |
| 3 | **認識エラーを区別していなかった**。取り消し（216・301）、無発話（1110）、Siri・音声入力が無効／端末内認識の準備がない（1700・201・102）などがすべて同じ文言 | 原因が分からない |
| 4 | 入力の形式（サンプルレート 0 など）・入力の有無を確認せずに録音を始めていた | 録音開始の失敗が分かりにくい |
| 5 | 認識サービスの利用可否（`isAvailable`）を許可の確認より前に調べていた | 初回は判定が不正確になりうる |

### 未確定（実機でしか確かめられない）
実機でどの経路が起きたかはログがないため確定していない。可能性: 上の 1・2、端末内の日本語認識の準備ができていない（`requiresOnDeviceRecognition`）、Siri・音声入力が無効、オーディオセッションの競合（読み上げ・他アプリ）。修正後は DEBUG ログで判別できる（下記）。

### 修正
- `MokorinRecognitionSession`（新規）: 1 回分の判断を音声の実装から分離。時刻を引数で受け取り、仮想の時計でテストできる
  - 無発話 8 秒・最長 30 秒は**録音が始まってから**数える。空の途中結果では話し始めたとみなさない。話し終え 1.8 秒は新しい文字を聞き取った時刻から
  - エラーを 取り消し／無発話／利用不可／その他 に分類。すでに聞き取った文字があれば、エラーでもその文字を送る
  - 終わったあとの結果・エラーは無視
- `SpeechRecognizerInput`: セッション ID を持ち、古いセッションのコールバック・タイマーを捨てる。タイマーは 1 つだけ（次の判定時刻に合わせる）。許可（音声認識 → マイク）の確認後に `isAvailable` を確認。オーディオセッション・入力の有無・入力形式・AudioEngine の開始を段階ごとに確認し、失敗したら片付けてから「マイクを開始できなかった」
- `MokorinVoiceController`: 録音ごとのトークンで古い結果を捨てる。権限の確認が終わるまで録音しない。確認中・送信中のマイクは無視（多重開始しない）。確認中に画面を閉じたら録音しない。取り消し・話さずに終えたときはエラーを表示しない
- 画面: 「マイクを準備しています」の表示、VoiceOver で録音開始と問題を読み上げ
- 原因ごとの文言: マイク権限なし／音声認識権限なし／認識サービス利用不可／声が聞こえなかった／マイクを開始できなかった／うまく聞き取れなかった（認識エラー）

### 実機で確認すべき診断（DEBUG ビルドのログ `[INSIGHT] mokorin voice …`。音声・文字・トークンは記録しない）
- `availability speechAuth=… mic=… available=… onDevice=…`: 許可と認識サービスの状態
- `session=XXXXXXXX stage=listening rate=… onDevice=…` / `stage=audio_session|input|format|engine_start failed code=…`: 録音開始のどの段階で失敗したか
- `session=XXXXXXXX end reason=… audio=… results=… speech=… error=<domain>/<code> elapsedMs=…`: 終了理由、音声バッファが届いたか、認識結果の件数、エラーの種類、経過時間
  - `audio=false` → マイクの入力が来ていない（オーディオセッション・入力経路）
  - `error=kLSRErrorDomain/201` や `kAFAssistantErrorDomain/1700` → Siri・音声入力が無効（設定 → 一般 → キーボード → 音声入力）
  - `error=kLSRErrorDomain/102` → 端末内の日本語認識の準備がない
  - `reason=no_speech_timeout elapsedMs≈8000` → 正しく 8 秒待ってから無発話
