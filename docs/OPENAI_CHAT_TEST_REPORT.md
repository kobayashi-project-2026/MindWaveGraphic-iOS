ブランチ `feature/overnight-integration-20261028`。ログ・スクリーンショットは `build/chat-logs/`（`.gitignore` の `build/` 配下。実行ごとに別ファイル）。

## 完成判定

| 段階 | 判定 | 根拠 |
|---|---|---|
| **LEVEL 1**: iPhone 上でチャット UI が動作する | **達成** | シミュレーター（iPhone 17 Pro / iOS 26.5）で、入口カード・同意カード・会話表示・作成中・失敗と再送信・サーバー未設定の案内を表示確認。会話は DEBUG の自動送信フックで実際の画面・送信処理を通して実行 |
| **LEVEL 2**: 自前サーバーと接続し、スタブで複数往復が成功する | **達成** | iOS → ローカルサーバー（`--stub-openai`）→ スタブ → iOS で **3 往復**（自動 E2E とシミュレーター画面の両方）。2 回目・3 回目の要求に、それまでの発言と返答が順番どおり含まれることをスタブの引用で確認 |
| **LEVEL 3**: 実際の OpenAI API と通信し、前の会話を踏まえた回答が返る | **未達成（未実施）** | API キー・課金の承認がないため実通信していない。**OpenAI のモデルが生成した返答はまだ一度も表示していない** |

スタブの返答は「受け取った履歴の件数・最初の相談・直前の質問」を機械的に引用するだけで、AI の生成ではない。画面には常に「スタブ応答（stub-model）・実際のAIではありません」と表示され、OpenAI の返答として表示されることはない（テストで確認）。

## 3. シミュレーターでの確認（スクリーンショット: `build/chat-logs/screens/`）

| 画面 | 確認内容 | ファイル |
|---|---|---|
| 「整える」タブ | 場面カードの下に「AIに相談する」カード | `guide-entry.png` |
| AI 相談（未同意） | 送信内容の説明と「同意して外部AIを使う」、入力欄の下に「端末内の定型アドバイスで応答します」 | `final-consent-card.png` |
| AI 相談（スタブで 3 往復） | 「面接前で緊張しています」→「さっき言っていた呼吸法を詳しく教えて」→「何回くらい繰り返せばいい？」。返答に「利用者 1 件・AI 0 件」「利用者 2 件・AI 1 件（最初のご相談『面接前で緊張しています』の続き）」「利用者 3 件・AI 2 件」。全返答に「スタブ応答・実際のAIではありません」 | `final-chat-3turns.png` |
| サーバー停止 | 「外部AIに届きませんでした」、端末内アドバイス（AIではありません）、「再送信」ボタン | `chat-server-down.png` |

| 設定 | 画面表示（追加した同意トグルはスクロール位置の下のため写っていない） | `final-settings.png` |

会話は DEBUG 専用の `MW_CHAT_AUTOPLAY` で送信した。これは入力欄の代わりに `ChatViewModel.submit` を呼ぶもので、通信・画面表示は通常と同じ経路を通る。
iOS の通信制限（ATS）による `http://127.0.0.1` への接続の遮断は起きなかった。

**未確認**: キーボードでの手入力と送信ボタンのタップ、キーボード表示時のスクロール、VoiceOver の読み上げ、リセット確認ダイアログの操作、設定画面のトグル操作（UI の自動操作手段がないため。ロジックは自動テストで確認）。
