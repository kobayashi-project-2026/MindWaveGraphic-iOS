## 1. 体験

測定前の状況選択画面（`ContextCalibrationView`）で、もこりんが質問し、利用者はボタンでも文章でも答えられる。

```
もこりん：こんにちは！今はどんな状況かな？下のボタンで選んでも、文章で教えてくれても大丈夫だよ。
あなた　：これから就職活動の面接があって、少し緊張しています
もこりん：面接や発表の前なんだね。緊張するよね。今は移動してきたところ？それとも座って落ち着いている？…
あなた　：さっき階段を上ってきました
もこりん：教えてくれてありがとう。面接や発表の前で、階段や移動の直後なんだね。この状況で測定してみようか？
確認　　：場面 面接 / 発表前　身体状態 階段 / 移動直後（もこりんの提案・変更できます）
［この状況で測定する］→ 既存の applyAndProceed() → MeasurementContext を保存 → mainApp
```

（上は外部AIを使わない「端末内の定型文」の場合の実際の表示。外部AIを使う場合は、返答文が AI の生成になる）

## 2. 責務の分担

| 担当 | 役割 | ファイル |
|---|---|---|
| もこりん（会話） | 質問・共感・状況の候補の提案。**確定・測定開始・数値計算はしない** | `Mokorin/MokorinContextViewModel.swift`, `Mokorin/MokorinContextServices.swift` |
| 画面 | 表示と、利用者の確定操作を既存の処理へ渡す | `Authentication/ContextCalibrationView.swift`, `Mokorin/MokorinBubble.swift`, `Mokorin/MokorinAvatarView.swift` |
| MeasurementContext | 確定した `scene: ContextScene` と `conditions: Set<BodyCondition>` の保持（変更なし） | `Domain/MeasurementContext.swift`, `AppFlowState.measurementContext` |
| 既存分析モジュール | 心拍・HRV と状況による数値計算（**変更なし**） | `StressScoreCalculator.swift`, `Analysis/` |
| 既存グラフィック | 計算結果の表示（変更なし） | — |
| サーバー | 会話から候補を構造化して返す（OpenAI Structured Outputs） | `server/src/context.ts`（`POST /v1/context-assist`） |

AI 相談（`ChatViewModel`）とは別の会話状態。状況選択画面を閉じると会話は破棄される（保存しない）。AI 相談の会話はログアウト時に消去（従来どおり）。

## 3. 会話の段階

| 段階 | 内容 | 進み方 |
|---|---|---|
| STEP 1 scene | 場面を確認 | 場面ボタン、または文章から場面の候補が出たとき |
| STEP 2 condition | 身体状態を確認（複数可、「特になし」は排他） | 身体状態ボタンで選んで「身体状態はこれで決定」、または文章から候補が出たとき |
| STEP 3 review | まとめて確認。選択はいつでも変更でき、変更するとまとめを更新 | — |
| STEP 4 確定 | 利用者が「この状況で測定する」を押す | 画面の操作のみ（AI・自動では進まない） |
| STEP 5 測定開始 | 既存の `applyAndProceed()`：初回は `authStatus = .mainApp`、メインアプリ内は `onComplete()` | 既存処理（重複実装なし） |

- 文章に場面と身体状態の両方が含まれていれば、まとめて STEP 3 へ進む
- 曖昧な文章（例「少し緊張しています」）では場面を決めず、同じ段階で追加の質問をする
- 「あとで選ぶ」（初回: 既定値で mainApp）・「変更しない」（メインアプリ内: 変更せず閉じる）は従来どおり
- 「やり直す」で会話と選択を最初の状態に戻す

## 4. 自由入力から状況を整理する方法

### 外部AI（同意＋サーバー設定があるとき）

`POST /v1/context-assist`（自前サーバー → OpenAI Responses API、`store: false`、Structured Outputs strict）

送信: 会話履歴（直近 12 件・1 発言 300 字まで）、現在の段階、画面で回答済みの場面・身体状態。**計測データの項目はない。**

受信（`ContextAssistResultDTO`）:

| 項目 | 型 | 内容 |
|---|---|---|
| `reply` | string | もこりんの返答（160 字まで） |
| `scene_candidate` | `ContextScene` の rawValue または null | 明言された場面 |
| `condition_candidates` | `BodyCondition` の rawValue の配列 | 明言された身体状態 |
| `needs_clarification` | bool | 追加で尋ねる必要があるか |
| `clarification_question` | string または null | 追加の質問 |

安全策: JSON Schema の enum で既存の値に限定 → サーバーで再検証（未知の値・型不正・医療的表現は 502）→ アプリでも enum へ変換できなければ不採用。「特になし」と他の状態が同時に来たら「特になし」を外す。返答に質問がない場合は、段階に合わせた定型の質問を添える。モデルへの指示で「緊張しているだけでは場面を決めない」「測定を開始したと言わない」「数値を推測しない」「診断しない」を明示。

### 端末内の判定（外部AIを使わない・失敗したとき）

`MokorinKeywordInterpreter`: 明確な言葉だけを候補にする（例: 面接・発表・プレゼン → 面接 / 発表前、階段・移動 → 階段 / 移動直後、コーヒー → カフェイン摂取後、特にない・座って → 特になし）。「緊張」「不安」だけでは場面を決めない。返答は定型文（「端末内の定型文」と表示）。

### 提案の扱い

候補は選択に反映され、場面ボタン・身体状態の行と確認エリアに「提案」と表示される。利用者がボタンで変えると提案表示は消える。**測定は利用者が「この状況で測定する」を押したときだけ始まる**（ViewModel には測定開始の処理がない）。

## 5. MeasurementContext への受け渡し

`ContextCalibrationView.applyAndProceed()`（既存）が `mokorin.measurementContext`（＝画面の `selectedScene` / `selectedConditions`）を `flowState.measurementContext` に保存する。
以前の `@State selectedScene / selectedConditions` を ViewModel に移しただけで、保存内容・遷移（初回は mainApp、メインアプリ内は onComplete で閉じる）は同じ。メインアプリ内の変更は従来どおり `MainTabView` の `onChange` で計測 ViewModel に反映され、計測 ViewModel の作り直しや Watch 通信の停止は起きない（AppRootContainerView が所有、変更なし）。

シミュレーターでの確認（DEBUG フック `MW_MOKORIN_AUTO_CONFIRM=1` で `applyAndProceed()` を呼ぶ）: コンソールに `context set: scene=interview conditions=["stairs"] -> mainApp`、画面はホームへ遷移（`app-console-autoconfirm-*.log`、`screens/f-after-confirm.png`）。

## 6. 外部AI・スタブ・定型文の動作

| 状況 | もこりんの動作 | 表示 |
|---|---|---|
| 外部AI 同意＋サーバー設定あり、OpenAI 実通信 | AI の返答と候補 | 「OpenAI（モデル名）」— **未検証（課金の承認待ち）** |
| 同上、サーバーがスタブ（`--stub-openai`） | 最後の発言のキーワードから機械的な候補と返答 | 「スタブ応答（stub-model）・実際のAIではありません」（橙色） |
| 未同意・サーバー未設定 | 定型の質問＋端末内の判定 | 「端末内の定型文」、ヘッダーに「端末内の定型文で案内中」 |
| APIキー未設定（503）・サーバー停止・タイムアウト・不正な応答 | 理由を表示し、端末内の判定で続行。ボタンで手動選択して測定できる | 「外部AIに接続できなかったため、端末内の判定で続けます（理由）」 |

同意は AI 相談と共通の「入力した文章を外部AIへ送る」同意（`ChatTextConsentStore`）。状況選択画面の「外部AIを使う（同意する）」または設定画面「AI相談・もこりんの文章を外部AIへ送信」で切り替える。

## 7. もこりんの画像

リポジトリ（全ブランチ）にもこりんの画像アセットはなかった。`MokorinAvatarView` は `Assets.xcassets` に **`Mokorin`** という名前の画像があればそれを表示し、ない場合は差し替え前提の簡易イラスト（白いもこもこの丸に目とほっぺ）を表示する。正式な画像が用意できたら、アセットを追加するだけで差し替わる（コードの変更は不要）。

## 8. データ保護

- 外部送信は文章送信の同意＋サーバー設定があるときだけ。送るのは会話・段階・選択中の場面と身体状態のみ
- 心拍・HRV・分析履歴は送らない（契約に項目がない。テストで要求 JSON を確認）
- APIキーはサーバーのみ。サーバー・アプリのログは件数・段階・候補の有無だけで、会話本文・候補の値は記録しない
- 医療的な診断・数値の推測をしない指示と、サーバー側の表現チェック
